### หน้าเฝ้าชั้นวางทำงานอย่างไร

โค้ดหน้าอยู่ที่ `src/watch.ts` ส่วนตรรกะล้วนอยู่ที่ `src/ui/watch-logic.ts` (มี test ใน `test/watch.test.ts`)

1. **หาช่องอัตโนมัติ** (เลือกหรือลากรูป / วิดีโอมาวางแล้วหาให้ทันที หรือกดปุ่ม): รันทั้งสอง model กับภาพเต็มหนึ่งครั้งเพื่อหาสินค้าแต่ละชิ้น
   (กล่องที่ซ้อนกันเกิน 60% ของกล่องเล็กเป็นชิ้นเดียว ใช้กรอบของ shelf model ก่อน: `toFoundItems`) → crop ทีละชิ้น (ขยาย 15%, ไม่ได้ชื่อที่ conf ≥ 0.5 ลอง 40%)
   ให้ model 110 คลาสตั้งชื่อ (`cropRect`, `cropLabel`) ไม่ได้ชื่อ = "สินค้าอื่น" สูงสุด 60 ชิ้น → แบ่งแถว แล้วรวมสินค้าชื่อเดียวกันที่ติดกันเป็นช่อง ช่องละไม่เกิน 6 ชิ้น (`autoSlots`)
   → ตัดช่องที่ตอนนั้นก็ดูว่างแล้วทิ้ง กันเตือนผิด · วิดีโอหยุดรอที่ภาพที่ใช้หาช่องจนกด *เริ่มเฝ้า* · ระหว่างหาช่องคืน main thread ให้ browser ทุกครั้งที่รัน model (มีแถบ progress)
2. แก้ชื่อ / ลบ / ลากเพิ่มช่องได้ · ช่องจำไว้ใน `localStorage` ของเครื่อง
3. **เฝ้า:** จับภาพหนึ่งภาพต่อรอบ แล้ว crop แต่ละช่องส่งให้ shelf model (เว้น 1 วินาทีหลังจบรอบ) · "มีของ" = มีกล่องใหญ่ ≥ 4% ของช่องและจุดกลางอยู่ใน 80% ด้านใน (`slotHasProduct`)
   · ว่างติดกันนานเท่าที่ตั้ง (เริ่ม 15 วินาที) → เตือน "ของหมด" · ของกลับมา 3 วินาที → ยกเลิก (`stepTrack`)
   · ภาพในช่องเปลี่ยนมาก (คนบัง / มือหยิบ) → วินาทีนั้นไม่นับ · วิดีโอจบแล้วบอกช่องที่ว่างแต่ยังไม่ถึงเวลาที่ตั้ง
4. **กรอบตามภาพเมื่อกล้องซูม / เลื่อน** (เปิดไว้เป็นค่าเริ่มต้น): จำช่องในพิกัดของภาพอ้างอิง (ภาพแรกที่เฝ้าหลังได้ช่องใหม่) แล้วทุกรอบรัน shelf model ทั้งภาพเพื่อหาว่าภาพอ้างอิงอยู่ตรงไหนในภาพนี้
   · ทุกรอบวัดก่อนว่ากรอบขยับจากรอบก่อนเท่าไร (`frameMotion` เทียบภาพรอบก่อนที่ขาดสินค้าเหมือนภาพนี้): ไม่ขยับ = กรอบอยู่ที่เดิมเป๊ะ (หยิบของออกไม่ทำให้กรอบขยับ)
   · ขยับ = ยกกรอบเดิมไปตามการขยับ (`composeView`) แล้วเทียบภาพอ้างอิงแก้คลาดเล็กน้อย (`pinView` ขยับได้ไม่เกิน 6% / 0.04)
   · วัดการขยับไม่ได้ 2 รอบติด (คนบังกล้อง) = หาจากภาพอ้างอิงอย่างเดียว: จับคู่กล่องกับภาพอ้างอิง (`fitViews`) แล้วปรับละเอียดด้วยการเทียบภาพขาวดำ 128×96 (`refineView`, `viewScore`)
   · ช่องที่อยู่ในภาพไม่ถึง 40% = "นอกภาพ" หยุดนับเวลา · เทียบไม่ชัด = ใช้ตำแหน่งล่าสุด
   · รองรับซูม ×0.33–×3 และเลื่อน ไม่รองรับการหมุนหรือเปลี่ยนมุมกล้อง

**แถบ "Agent กำลัง…" ใต้ภาพ** (`src/flow.ts`, ขั้นและข้อความสรุปอยู่ที่ `src/ui/flow-logic.ts` มี test ใน `test/flow.test.ts`):
หนึ่งการ์ดต่อหนึ่งขั้นของงาน เรียงตามที่ `watch.ts` ทำจริง แต่ละการ์ดบอกว่าใครทำ (Agent + model ไหน หรือเว็บ) ผลสรุปของขั้น และจำนวน call / ms
· เฝ้า: ① ตรวจภาพเต็ม (model ชั้นวาง) → ② ตามกล้อง + จับคู่กล่องกับช่อง (เว็บ) → ③ ครอปเช็กช่องที่ยังไม่ชัด (model ชั้นวาง) → ④ สรุป + จับเวลาว่าง (เว็บ)
· หาช่องอัตโนมัติ: ① หาสินค้าทั้งภาพ → ② ระบุชื่อทีละชิ้น → ③ รวมเป็นช่อง + ยืนยันว่ามีของ
· ระหว่างรอบ มีแค่การ์ดของขั้นที่กำลังทำที่เปลี่ยน ขั้นที่ยังไม่ถึงแสดงผลรอบก่อนแบบจาง จึงไม่กระพริบตามการเรียก `detect()` แต่ละครั้ง (ครอปบน WebGPU ~30 ms) · แถวล่างนับว่ารอบนี้เรียกแต่ละ model กี่ครั้ง
· ตารางช่องด้านขวาบอกว่าแต่ละช่องตัดสินจากอะไรในรอบล่าสุด: ภาพเต็ม / ครอป / ถูกบัง / รอบหน้า (ครอปไม่ทัน ใช้ผลรอบก่อน) / นอกภาพ · ตัวเลขเวลา การเทียบวิธีตรวจ log และ JSON อยู่ใน "สำหรับนักพัฒนา"
บนภาพหลัก (รูป วิดีโอ และกล้อง) มีกรอบเล็งของ agent, กรอบทุกช่องพร้อมสถานะ และกรอบสินค้าจากผลภาพเต็มล่าสุด · บนวิดีโอผลช้ากว่าภาพราวหนึ่งรอบ มุมล่างจึงบอกว่ามาจากภาพไหนและช้ากว่าภาพกี่วินาที ผลที่เก่ากว่า 2.5 วินาทีไม่วาด (`drawStage`) · snapshot ด้านขวาคือภาพที่จับไปตรวจจริง พร้อม frame ID, timestamp และอายุภาพ/ผลตรวจ
· ภาพเคลื่อนไหวใช้แค่ `transform` / `opacity` จึงยังลื่นขณะ model (WASM) ทำงานบน main thread · ก่อนเรียก model ทุกครั้งรอให้จอวาดหนึ่งเฟรมก่อน (`painted`) และตอนวิดีโอเล่น จับภาพหลังวิดีโอแสดงเฟรมใหม่แล้วเท่านั้น ใช้เวลาของเฟรมนั้นเป็นเวลาภาพ (`presentedFrame`, `requestVideoFrameCallback`) กัน model ได้ภาพเก่าที่ติดเวลาปัจจุบัน
· วิดีโอเล่นต่อเนื่องไม่พักรอผล: รอบหนึ่งจับภาพล่าสุดหนึ่งภาพ ตรวจเสร็จแล้วจึงจับภาพถัดไป (ไม่เกิน 1 ภาพต่อวินาที) · ปิดแถบได้ที่ "แสดงการทำงานของ agent"
· สถานะช่องบนจอมีแค่ มีของ / ว่าง x/15 วิ (นับถอยหลังก่อนเตือน) / ของหมด / รอตรวจ (ยังไม่มีผลหรือผลเก่า) / นอกภาพ (`statusText`)
· Controls ใต้ภาพ: เล่น/พัก, seek, เวลาปัจจุบัน/ความยาว และความเร็ว 0.5–2×; overlay ไม่ทับ controls
· เริ่มเฝ้าเริ่ม timer ใหม่และเล่นไฟล์; พักวิดีโอพักการเฝ้าชั่วคราวโดยรักษา timer; หยุดเฝ้าพักไฟล์ด้วย แต่ไม่พักกล้องสด
· Seek ยกเลิกผลที่ค้างและ reset timer/ประวัติแจ้งเตือน โดยรักษาช่องและพิกัดอ้างอิง; เปลี่ยนแหล่งภาพล้างพิกัดที่เป็นของภาพเก่าด้วย
· ทุกช่องในรอบใช้เวลา capture เดียวกัน: `video.currentTime` สำหรับไฟล์, `performance.now()` สำหรับกล้อง
· เวลา `detect()` รวมแสดงแยกจากเวลาทั้งรอบ (รวมรอ/นำเสนอ); `latency_ms` ของ agent รวม preprocess/run/postprocess ไม่ใช่ inference ล้วน
· บันทึก `detect()` แบบละเอียดและ JSON ล่าสุดอยู่ใน "บันทึกการเรียก agent (สำหรับนักพัฒนา)" ด้านขวา

## agent.version

| ค่า | ผล |
|---|---|
| `mock` | ใช้ `src/mockAgent.ts` (กล่องปลอม) สำหรับ dev โดยไม่ต้องดาวน์โหลด release |
| `vX.Y.Z` | โหลด `<base>agent/vX.Y.Z/shelf-agent.js` ซึ่ง `make fetch-agent-release` วางไว้ใน `public/agent/vX.Y.Z/` ตอน build — ไม่ commit |

ตอนนี้ทั้ง `agent.version` และ `agent-shelf.version` = **`v0.3.2`** (model 110 คลาส + shelf model ใน release เดียว, ~56 MB)
`agent-shelf.version` ใช้กติกาเดียวกัน · `make fetch-agent-release` ดึงทั้งสองเวอร์ชัน · `make bump-agent` ขยับแค่ `agent.version`
หน้าเฝ้าชั้นวางต้องใช้ release ที่มีทั้งสอง model (`v0.3.x`) และ `v0.3.2` ขึ้นไปสำหรับ `shelfOnly` · ถ้าเป็น `v0.2.x` ทุกช่องจะได้ชื่อ `product`

ค่าอื่นทำให้ build ล้ม (`vite.config.ts: readAgentVersion`) · เว็บคุยกับ agent ผ่าน `src/agent.ts` ที่เดียว ตาม interface ใน `src/agent-contract.ts`
(สำเนาของ `retail-shelf-agent/src/types.ts` แก้ที่หนึ่งต้องแก้อีกที่)

## Agent release (SPEC §7)

```bash
make fetch-agent-release                  # ดึง release ตาม agent.version + agent-shelf.version ลง public/agent/<v>/ แล้วตรวจ SHA256SUMS / manifest / contract
make bump-agent                           # ไป patch ล่าสุดของ minor เดิม → npm test + npm run build (พังเมื่อไรคืน pin เดิม, ไม่ commit ให้)
make bump-agent AGENT_VERSION=v0.4.0 ALLOW_MINOR=1   # ข้าม minor ต้องใส่ ALLOW_MINOR=1 · ถอยเวอร์ชันไม่ได้
make agent-lag                            # บอกว่ามี patch ใหม่กว่า pin ไหม (CI ขึ้นเป็น warning)
```

ใช้ release ในเครื่องแทน GitHub ได้: `AGENT_RELEASES_DIR=../retail-shelf-agent/release make fetch-agent-release`
(โฟลเดอร์ที่มี `vX.Y.Z/` จาก `npm run package` ของ agent) · โค้ดอยู่ที่ `scripts/agent-release.mjs` · test: `test/agent-release.test.ts`

CI (`.github/workflows/ci.yml`): `npm ci` → `make fetch-agent-release` → `npm test` → `npm run build` → `make agent-lag` (warning)
Deploy: push `main` → `.github/workflows/pages.yml` (`npm ci` → `make fetch-agent-release` → `npm test` → `npm run build` → Pages)
